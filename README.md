# ML Learning Coach: a QLoRA fine-tuned Qwen2.5-1.5B-Instruct, served locally with Streamlit

A beginner-friendly machine learning tutor. We fine-tuned our **own QLoRA adapter** on top of
`Qwen/Qwen2.5-1.5B-Instruct` and serve it in a Streamlit chat app that runs **entirely on the local
computer**. No OpenAI, Anthropic, Ollama or any other hosted model is called. After the first download of
the base model (about 3 GB) the app works fully offline.

## What the coach does
| Mode | You write | The coach answers with |
|---|---|---|
| **Explain** | "What is overfitting?" | `Simple explanation` / `Example` / `Check yourself` (one guiding question) |
| **Check my understanding** (use-case feature, sidebar form) | a topic and your own explanation | `Verdict` (Correct / Partly correct / Wrong), `What is right`, `What to improve`, `Think about it` |
| **Follow-ups** | "give me another example", or an answer to its question | uses the earlier turns of the conversation |
| **Off-topic** | "give me a pancake recipe" | a short, polite redirect to machine learning |

Other app features: token-by-token streaming, conversation memory, regenerate button, chat history saved to a file,
optional "show the base model's answer" comparison, loading indicator, readable error messages.

## Quick start (run the app)
Requirements: Python 3.10+, about **4.5 GB of free RAM** on a CPU (see "Performance"), or a CUDA GPU.

**Tested with:** Python 3.12.4, torch 2.15.0 (CPU build), transformers 5.22.1, peft 0.21.2, streamlit 1.66.1, Windows. The code adapts to older transformers versions where it matters (`dtype`/`torch_dtype`, `eval_strategy`), but only this combination was tested end to end.

```bash
pip install torch                     # CPU build is enough; skip if already installed
pip install -r requirements.txt       # transformers, peft, accelerate, safetensors, psutil, streamlit
```

**Get the adapter.** The trained adapter (our own QLoRA run, about 70 MB) is included in this repository in the folder `adapter/`, next to `app.py`. It must contain at least `adapter_config.json` and `adapter_model.safetensors` (the other files are the tokenizer files and a model card). To create it yourself, run training notebook 2 (see below): it writes the same folder to Google Drive and as `adapter.zip`.

```bash
python -m streamlit run app.py        # then open http://localhost:8501
```
Use `python -m streamlit` (not just `streamlit`) so that the same Python that has the installed packages is used.

* The first start downloads the base model into the Hugging Face cache (internet needed once). Later starts load it
  from the local cache without contacting the Hub, so you can disconnect from the internet.
* On a GPU the model is loaded in fp16 automatically; on a CPU it is loaded in bf16 (about 3.4 GB of RAM).
* Base model: `Qwen/Qwen2.5-1.5B-Instruct`. Adapter path: `./adapter` (change `DEFAULT_ADAPTER_DIR` in `engine.py`).

Quick checks from the terminal (no browser needed): `python test_engine.py` and `python test_conversation.py --quick`.

## How the fine-tuning was done (reproduce it)
**1. Data.** The training examples were written by hand in code (`examples_part*.py`) with the help of an AI
assistant and reviewed by the author. They cover 25 ML topics: for every topic one explanation plus three
"check my understanding" cases (a correct, a partly correct and a wrong student claim), 16 multi-turn follow-up
conversations and 16 off-topic requests. The answer format is produced by code (`fmt.py`) and every example is
validated (`validate.py`).
```bash
python build_dataset.py        # expects: Total: 132 examples ... format check passed
python view_dataset.py list
python make_test_prompts.py    # 12 held-out prompts (not in the training data)
```
**2. Training** (Google Colab, free T4 GPU). In each notebook choose Runtime > Change runtime type > T4 GPU. Put
`data/train.jsonl` and `data/test_prompts.json` in a Drive folder `ml-coach-en` (or upload when asked) and run, in order:

| Notebook | Output |
|---|---|
| `01_baseline.ipynb` | answers of the **untouched** base model (`baseline_outputs.json`) |
| `02_train_qlora.ipynb` | the adapter (`adapter/`) and the evidence files (`training_info.json`, `training_log.json`, `loss_curve.png`) |
| `03_evaluate_adapter.ipynb` | reloads the adapter from disk with `PeftModel.from_pretrained(base, adapter_dir)`, `finetuned_outputs.json`, `before_after.md` |

**Setup used (also stored in `results/training_info.json`)**

| | |
|---|---|
| Base model | `Qwen/Qwen2.5-1.5B-Instruct`, 4-bit NF4 (double quantization), fp16 compute |
| LoRA | r=16, alpha=32, dropout 0.05, on q/k/v/o/gate/up/down projections: 18,464,768 trainable parameters (1.18%) |
| Data | 132 examples: 120 train / 12 validation (dataset SHA-256 prefix `c2f7396fb969`) |
| Training | 3 epochs, batch 2 x 4 accumulation = 8, learning rate 2e-4 cosine, warmup, `paged_adamw_8bit`, fp16, seed 42 |
| Loss | computed **only on the coach's answers** (system prompt and student messages are masked with -100) |
| Hardware / time | Colab T4, 230 seconds |

**Loss.** Train loss fell from 2.11 to 0.81. Validation loss: 1.33 (epoch 1), 1.21 (epoch 2), 1.22 (epoch 3). It stopped
improving after epoch 2, so we kept 3 epochs and did not train longer. Curve: `results/loss_curve.png`.

## Results: before and after fine-tuning
Same 12 held-out prompts, same system prompt, greedy decoding. "Before" is the untouched base model
(it also sees the full system prompt, so this is a strong baseline).

| Measure | Before | After |
|---|---|---|
| Answer follows the required format (12 prompts) | 4/12 | **10/12** |
| Correct verdict on 5 claims (3 wrong, 2 correct) | 2/5 | **5/5** |
| Gives a *new* example when asked for a different one | no | **yes** |

Examples (full text in `results/before_after.md`):

*Student claim: "In kNN, the smaller k is, the more stable the model becomes."*
* Before: `Verdict: Correct ... No further improvement needed as the statement is accurate.`
* After: `Verdict: Wrong. What is right: A small k means each new prediction depends on its neighbors, so the result can be very sensitive to noise. What to improve: ... a large k averages over many neighbors ...`

*Student claim: "A random forest is just one very deep tree."* Before: the base model ignored the checking task and
answered in explanation format. After: `Verdict: Wrong` with a correct explanation that the forest averages many trees.

*Follow-up memory:* after "What is gradient descent?", the question "Can you give me a different example?" is answered
inside the same topic (the base model switched to an unrelated "shortest path" example).

## How the app works
* **Model loading** (`engine.py`): `AutoModelForCausalLM.from_pretrained(base)` followed by
  `PeftModel.from_pretrained(base, "adapter")`. Offline-first: the Hugging Face cache is used without contacting the Hub.
* **Streaming**: `generate()` runs in a background thread with a `TextIteratorStreamer`; the UI prints the pieces as they
  arrive. A stop signal cancels the generation if the user leaves the page.
* **Memory**: the chat history is kept in `st.session_state`; the model receives the last 12 messages.
* **Speed-up for slow CPUs**: the attention cache of the system prompt (and of the previous conversation turns) is reused,
  so only new text is processed. On the test CPU this cut the wait for the first words from 36 s to 4 s.
* **Errors**: a missing/broken adapter, not enough free memory, out-of-memory and a missing base model show a readable
  message with a "Try again" button instead of crashing (tested by renaming the adapter folder).

## Performance (what to expect)
Measured on a laptop: Intel 8th-gen quad-core (AVX2), 11.8 GB RAM, no GPU, Windows, bf16.

| | |
|---|---|
| Model load | about 14 s, 3.4 GB of RAM |
| First words | about 4 s with the prompt cache (about 36 s without) |
| Generation speed | about 2.9 tokens/s from the terminal, about 1.3-1.5 tokens/s in the browser while other programs run |
| A full answer (about 150 tokens) | roughly 1-2 minutes on this CPU; a few seconds on a GPU |

The app needs roughly **4.5 GB of free RAM** on a CPU. With many browser tabs open, Windows starts swapping and answers
become several times slower; close other programs for best results (the sidebar shows the free memory).

## Limitations (please read)
* A 1.5B model makes **factual mistakes** in the explanation text, even when the verdict is right. We saw wrong numbers in
  a precision/recall example and a wrong description of ensemble learning (a topic that was not in the training data).
  Fine-tuning taught the model the *behaviour* (format, Socratic style, verdicts, memory), not new knowledge.
* Follow-up answers sometimes drop the structured format (for example a reply starting with "Sure!").
* The "What is right" part of a verdict can contradict the verdict ("Nothing important is wrong here" next to
  `Verdict: Wrong`). Off-topic requests are not always redirected briefly (one pasta-recipe test got a mini lecture).
* 5/5 correct verdicts is measured on only 5 test claims; it shows an improvement, not a guarantee.
* The format check is strict (for example, an off-topic answer must contain exactly one question mark); one of the two
  "format failures" was a harmless extra question.

## Earlier experiment: an Azerbaijani coach (v1)
The first version was an Azerbaijani-language coach with 143 hand-written examples (same pipeline, 3 epochs; train loss
2.50 -> 1.33, validation loss 1.92 -> 1.56). The adapter learned the answer format (4/12 -> 11/12 answers in the right
format) but produced invented words and gave the right verdict on only 2/5 claims. The base model's Azerbaijani is weak and
about 8,300 words of training text cannot teach a language. We therefore switched to English, where the base model is
strong. The v1 adapter and its data are not part of this repository.

## Traceability (training evidence)
* `results/training_info.json`: finish time (UTC), GPU, dataset hash, all hyperparameters, loss values, library versions.
* `results/training_log.json` and `results/loss_curve.png`: the loss from the Trainer log.
* `notebooks/02_train_qlora.ipynb`: the exact training code; `examples_part*.py`: the exact training data.
* No code in this project downloads or loads an adapter from anywhere; `adapter/` is the output of notebook 2.
* No external LLM API is used. The only network access is the one-time download of the base model by `from_pretrained`.
  Streamlit's usage statistics are turned off in `.streamlit/config.toml`.

## Troubleshooting
| Message / symptom | Meaning and fix |
|---|---|
| `No module named 'peft'` when starting the app | `streamlit` started from a different Python. Use `python -m streamlit run app.py` |
| `ERR_CONNECTION_REFUSED` on localhost:8501 | the app is not running; start it again |
| "Adapter not found in 'adapter'" | put the adapter folder next to `app.py` |
| "Not enough free memory" or very slow answers | close the browser tabs and other programs; lower the answer length in the sidebar |
| first start fails with a download error | the base model must be downloaded once, so an internet connection is needed the first time |
